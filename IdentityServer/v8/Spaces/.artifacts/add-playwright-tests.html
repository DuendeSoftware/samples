Overview

Add end-to-end Playwright tests using Aspire to host the Spaces IdentityServer sample. Tests verify login flows across spaces (hostname-based and path-based) and client credentials token requests.

The Spaces sample runs on https://localhost:5000 with spaces resolved by hostname (space1.dev.localhost:5000, space2.dev.localhost:5000) and path (/space3). It uses SQLite in-memory, so no external infrastructure is needed.

Testing Conventions

  • All element interactions and assertions use data-testid attributes for deterministic selection.
  • Tests use page.GetByTestId("...") (Playwright's built-in data-testid support).
  • Tests navigate via UI links from the home page. No hardcoded URLs for internal pages.
  • Playwright traces (screenshots, snapshots, sources) are saved to artifacts/playwright-traces/ for CI debugging.
  • Browser runs headless when the CI environment variable is set.

Execution Order

  1. Update Directory.Packages.props (add package versions)
  2. Create aspire/AppHost/ (AppHost.csproj + Program.cs)
  3. Add data-testid attributes to Index.cshtml and Login.cshtml
  4. Create tests/Spaces.PlaywrightTests/ (all infrastructure + test files)
  5. Update Spaces.slnx
  6. Run dotnet build to verify compilation
  7. Run dotnet test to verify tests pass (requires *.dev.localhost DNS resolution)

Decisions

Decision 2025-07-23: Use Aspire to host the application with port pinned to 5000. Tests navigate via UI links and use data-testid selectors exclusively.
  • Aspire hosting: Even though Spaces has no external dependencies, Aspire provides consistent app lifecycle management and health checks.
  • Port pinning: Fixed at 5000 to match the seeded space match patterns (which include the port in their origin).
  • UI navigation: Tests follow links from the home page rather than hardcoding internal URLs, mirroring real user behavior.
  • data-testid selectors: Decouples tests from CSS classes and markup structure. Playwright's GetByTestId is the primary locator strategy.
  • Space3 test scope: Only verifies redirect to the external IDP (demo.duendesoftware.com), not full external sign-in completion.

Risks and Open Questions

Risks to monitor during implementation.
  • *.dev.localhost DNS resolution: Most modern OSes resolve *.localhost to 127.0.0.1, but *.dev.localhost may need a hosts file entry or DNS configuration in CI.
  • Port conflict: Port 5000 is pinned. Tests will fail if another process occupies that port.
  • External IDP availability: The space3 test depends on demo.duendesoftware.com being reachable for the redirect assertion. If the external service is down, the test will fail.
